# Semantic Stacked PR: Base → Generated → Fix → Tests

A normal stacked PR splits a change by **increments**. This skill splits it by **meaning**: each PR in the stack contains exactly one kind of code, so a reviewer knows the required effort before opening it.

The goal is review cost, not tidiness. A 900-line diff where 700 lines are a regenerated API client hides the 40 lines that matter. Separating the layers makes the 40 lines the entire content of one PR.

## Layers

Bottom (closest to trunk) to top:

| # | Layer | Content | Review effort |
|---|-------|---------|---------------|
| 1 | Base | Hand-written codegen input: OpenAPI documents, migrations, `.proto`, GraphQL SDL, `schema.prisma` | High — this is the contract, and it is the reason everything above exists |
| 2 | Generated | Output of running the generator over layer 1 | None — verify the command, not the diff |
| 3 | Fix | The actual behavior change | High — all implementation scrutiny belongs here |
| 4 | Tests | Tests and fixtures locking in the new behavior | Low — read as the description of what layer 3 now does |

"Base" is the layer everything else is derived from — the hand-written input a generator reads. It is not a PR's base branch; the branch a stack is built on is always called the **trunk** in this document.

The order is the dependency order, which is what makes every PR self-contained:

- The generator cannot run without its input, so the base layer is at the bottom.
- The fix imports the generated code, so it sits above it and compiles on its own.
- The tests are based on the fix, so the behavior they assert already exists where they live.

No PR in the stack is red by design, and branch protection never blocks the atomic merge. `gh stack merge <pr>` can also land the stack partially, up to whichever layer is ready.

## Prerequisites

```bash
gh extension list | grep -q gh-stack || gh extension install github/gh-stack
```

Labels `generated` and `test` mark the layers whose review effort is not proportional to their size. Create them if the repository does not have them:

```bash
EXISTING=$(gh label list --json name --jq '.[].name')
grep -qx generated <<<"$EXISTING" || gh label create generated --color BFD4F2 \
  --description "Machine-generated output; verify the generator, not the diff"
grep -qx test <<<"$EXISTING" || gh label create test --color C2E0C6 \
  --description "Tests only; no behavior change"
```

Label creation needs write access. If it fails, continue without labels and say so in the final report.

## Workflow

### Step 1: Determine the entry mode

```bash
git branch --show-current
git status --short
```

**Mode A — uncommitted changes on a trunk branch** (`main`, `master`, `develop`, `development`, `staging`, `release`): the normal case. Continue.

**Mode B — uncommitted changes on a feature branch with no PR yet:** treat the branch's merge base as trunk and continue.

**Mode C — a feature branch that already has commits:** the change must be unpacked before it can be split.

```bash
MERGE_BASE=$(git merge-base HEAD origin/<trunk>)
git reset --soft "${MERGE_BASE}"
```

This rewrites local history. Ask the user before running it. If the branch already has an open PR, stop instead — splitting would require a force push over a branch under review.

If there are no changes at all, report and stop.

### Step 2: Classify every changed file

```bash
git status --porcelain
git diff --stat HEAD
```

Assign each file to exactly one layer. Classify by evidence, not by guesswork.

**Generated** — decided first, because its signal is the strongest and it overrides every other rule:

```bash
grep -lE '@generated|Code generated by|DO NOT EDIT|auto-generated' <files>
```

- Lockfiles: `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock`, `poetry.lock`, `go.sum`, `uv.lock`
- Codegen output: `*.gen.*`, `*.generated.*`, `*_pb2.py`, `*.pb.go`, generated OpenAPI/GraphQL clients
- Build and vendor output: `dist/`, `build/`, `vendor/`, `node_modules/`
- Snapshots: `__snapshots__/`, `*.snap`

**Base** — hand-written files that a generator reads:

- OpenAPI / Swagger documents: `openapi.{yaml,json}`, `swagger.{yaml,json}`, `api/**/*.yaml`
- Database migrations and schema definitions: `migrations/`, `db/migrate/`, `schema.prisma`, `*.sql` under a migration directory
- IDL: `*.proto`, `*.thrift`, `*.avsc`
- GraphQL SDL: `*.graphql`, `*.graphqls` — unless it carries a generated header, in which case it is Generated

A file that both matches a Base pattern and carries a generated header is **Generated**. The header wins.

**Tests**:

- `*.test.*`, `*.spec.*`, `*_test.go`, `*_test.py`, `test_*.py`, `*Test.java`, `*Test.php`
- `__tests__/`, `tests/`, `spec/`, `e2e/`, `cypress/`, `playwright/`
- Fixtures reachable only from the above

**Fix** — everything else, including config and docs that describe the behavior change.

Ambiguous files (a fixture also imported by production code, a hand-edited file inside a generated directory) go to the **Fix** layer. Over-including in a layer that gets read carefully is safe; under-including is not.

Show the user the classification as a table before creating anything. Do not ask for approval on an obvious split — only when a file's layer is genuinely unclear.

### Step 3: Check for a codegen drift check

The Base PR contains a contract change without its regenerated output. Repositories that verify generated code is current will fail on it:

```bash
grep -rlE 'diff --exit-code|git diff --quiet' .github/workflows/
```

If such a check exists and covers the generator used here, the Base PR is red on its own, and `gh stack merge` is all-or-nothing under branch protection. Report it and offer the fallback: fold Base and Generated into a single bottom PR, keeping them as two separate commits so the contract can still be read alone. Let the user choose. Do not fold silently — it puts the largest diff back next to the contract.

### Step 4: Skip empty layers

Create a PR only for a layer with at least one file.

- Two or more non-empty layers → build the stack. A change with no codegen is simply a two-layer stack: Fix → Tests.
- One non-empty layer → there is nothing to split. Delegate to `/git-workflow` for a single PR and stop.

### Step 5: Build the stack bottom-up

Derive one slug for the whole change (kebab-case, English, from the fix layer's content — e.g. `null-response-handling`). `<type>` is the conventional commit type of the overall change (`feat`, `fix`, `refactor`).

| Layer | Branch |
|-------|--------|
| Base (bottom) | `<type>/<slug>-base` |
| Generated | `chore/<slug>-generated` |
| Fix | `<type>/<slug>` |
| Tests (top) | `test/<slug>` |

Create the bottom branch, then commit its files:

```bash
gh stack init "<type>/<slug>-base"
git add <base files>
git commit -m "<type>: <contract change>"
```

Stack each subsequent layer on top. `gh stack add` commits what is staged, so stage the layer's files first:

```bash
git add <generated files>
gh stack add "chore/<slug>-generated" -m "chore: regenerate <what> for <slug>"

git add <fix files>
gh stack add "<type>/<slug>" -m "<type>: <what changed>"

git add <test files>
gh stack add "test/<slug>" -m "test: cover <behavior>"
```

Never use `git add -A` or `gh stack add -A` here — staging everything defeats the split. Stage explicit paths only.

Verify before pushing anything:

```bash
gh stack view --short
git status --short   # must be empty; a leftover file means a file was missed
```

### Step 6: Submit and label

The interactive editor cannot be driven from this session, so submit non-interactively. `--auto` creates every PR as a draft with a generated title:

```bash
gh stack submit --auto
```

Then read back the branch-to-PR mapping:

```bash
gh stack view --json
```

Inspect the returned JSON for the branch name and PR number of each entry, then rewrite each PR with a real title, body, and label:

```bash
gh pr edit <number> --title "<title>" --add-label <generated|test> --body "$(cat <<'EOF'
<body>
EOF
)"
```

- Generated PR → `--add-label generated`
- Tests PR → `--add-label test`
- Base and Fix PRs → no label; they are reviewed normally

Titles follow conventional commit format, English, 70 characters or fewer.

### Step 7: PR bodies

Every PR body starts with the same three lines so the reviewer can triage from the list view:

```markdown
**Layer:** Base | Generated | Fix | Tests
**Review effort:** High — this is the contract | None — verify the command, not the diff | High — all scrutiny here | Low — this is the description
**Stack:** 1 of 4 · part of <slug>
```

Then, per layer:

**Base** — what the contract now says, and what will be regenerated from it.

```markdown
## Contract change

- <what changed in the interface, schema, or migration>

The regenerated output is in <generated PR link>, the next PR in the stack.
```

**Generated** — the exact command that produced the output.

```markdown
## Regenerated by

    <command>

No hand edits. Reviewing the diff line by line is not useful; re-run the command to verify.
```

**Fix** — the real PR. Follow the repository's PR template when one exists (`.github/pull_request_template.md`, then `.github/PULL_REQUEST_TEMPLATE.md`), otherwise Summary / Changes / Test Plan. Link the tests PR as the guard on this change.

**Tests** — what is asserted, and where the behavior comes from.

```markdown
## What this asserts

- <behavior>

Based on <fix PR link>, below this PR in the stack. These tests pass here and fail
without it — that is what makes them a regression guard.
```

### Step 8: Mark ready and report

```bash
gh pr ready <number>   # for each PR, bottom to top
gh stack view --short
```

Report the stack to the user bottom-to-top with each PR's URL, layer, label, and line count, plus the merge command:

```bash
gh stack merge --yes --squash
```

## Rules

- Split by meaning, never by size. Four layers is the maximum; do not invent a fifth.
- A file belongs to exactly one layer. A generated header overrides every other classification rule. Ambiguous files go to Fix.
- Stage explicit paths. `git add -A` and `gh stack add -A` are forbidden in this workflow.
- Never create an empty PR. One non-empty layer means no stack.
- Never force push, and never restructure a branch that already has an open PR.
- Label the Generated and Tests PRs. If the labels cannot be created, report it rather than skipping silently.
- Verify `git status --short` is empty after Step 5. A leftover file is a classification bug, not noise.
- Stop and report on the first command failure. A half-built stack is worse than none.

## Language

PR titles and bodies follow the repository's dominant language, as determined from `git log` and existing PRs, unless the user specifies otherwise. Branch names and commit types are always English.

## Examples

### OpenAPI change with a client regeneration and a fix

```
Changed: 17 files, 1024 lines
  Base:      openapi.yaml                                    (31 lines)
  Generated: src/api/client.gen.ts, pnpm-lock.yaml          (843 lines)
  Fix:       src/order/retry.ts                              (22 lines)
  Tests:     src/order/__tests__/retry.test.ts               (47 lines)

  #61  feat/retry-backoff-base       Base        31 lines  —          effort: high
  #62  chore/retry-backoff-generated Generated  843 lines  generated  effort: none
  #63  feat/retry-backoff            Fix         22 lines  —          effort: high
  #64  test/retry-backoff            Tests       47 lines  test       effort: low

Reviewer reads the contract in #61 and the implementation in #63. #62 is skipped
by its label. `gh stack merge 63` lands everything except the tests if #64 needs work.
```

### No codegen involved

```
Changed: 4 files
  Fix:   src/auth/session.ts, src/auth/token.ts
  Tests: src/auth/__tests__/session.test.ts

  #70  fix/session-expiry   Fix    —     effort: high
  #71  test/session-expiry  Tests  test  effort: low
```

### Codegen drift check present

```
.github/workflows/ci.yml runs `git diff --exit-code` after `make generate`
→ the Base PR would be red alone

Asked the user: fold Base + Generated into one bottom PR (two commits), or accept
the red check and merge the stack atomically.
```

### Nothing to split

```
Changed: 3 files, all under src/  → single layer (Fix)
→ delegate to /git-workflow, no stack created
```
