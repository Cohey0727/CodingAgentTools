# 2026-09-27 — OpenCode v2 移行

OpenCode の v2(`curl -fsSL https://opencode.ai/v2/install | bash` で入る。
手元では v2.0.18)はプラグイン API を変えた。v1 のプラグインは v2 では
一切動かず、起動のたびにエラーが出る。公式の移行ガイドは
https://opencode.ai/v2/docs/build/plugins/migrate-v1 。

## v2 で変わったこと

- サーバープラグインは default export に `{ id, setup }`(または
  `{ id, effect }`)が必須。v1 の `export const plugin = ...` という
  名前付き export は
  `Plugin must export a default definition with an id and an effect or setup function.`
  で弾かれる。
- TUI プラグインも default export に `{ id, setup }` が必須。v1 の
  `{ id, tui }` は `Invalid V2 TUI plugin module: <名前>` で弾かれる。
- 登録は `setup(ctx)` の中でドメインごとに行う。コマンドは
  `ctx.command.transform`、ツールは `ctx.tool.transform`(JSON Schema)、
  イベントは `ctx.event.subscribe`。v1 の `command.execute.before` フック
  や `event` コールバックに直接相当するものはない。
- イベントは `{ type, data }` 形式(v1 の `properties` ではない)。ターン終端は
  `session.execution.succeeded` / `.failed` / `.interrupted`、トークン実績は
  `session.step.ended` の `tokens`(`session.idle` はプラグインバスに流れない)。
- プラグイン SDK のスコープが `@opencode-ai/plugin` から
  `@opencode/plugin` に変わった。必要なものはすべて `ctx` に載るので、
  npm import しないプラグインはどこに置いても解決される。
- 設定の場所とキー: TUI プラグインの登録先は `tui.json` から
  `~/.config/opencode/cli.json` の `plugins` に移る(opencode.json の
  `plugin` は `plugins` にリネーム、旧キーも自動で読まれる)。
- `opencode plugin -g` は廃止。`opencode plugin add` / `update` /
  `remove` / `list` / `check` になった(`-g` フラグはない)。

## プラグインごとの状況

| プラグイン | 状況 |
|---|---|
| oc-tps | 0.0.11 (2026-09-20) から v2 対応。`opencode plugin update` で直る |
| @tarquinen/opencode-dcp | 3.2.0 で v2 対応済み。そのままでよい |
| @slkiser/opencode-quota | 未対応。最新 4.10.5 でも v1 形式。v5.0.0 で対応予定([issue #293](https://github.com/slkiser/opencode-quota/issues/293)) |
| opencode-handoff | 未対応。最終リリース 2026-02、[issue #33](https://github.com/joshuadavidthomas/opencode-handoff/issues/33) は open のまま |
| goal.js / loop.js(このレポ) | v2 に移植済み。コマンドは `ctx.command.transform` で自前登録するので `opencode/command/*.md` は廃止、`bin/opencode-plugin.template` の shim も廃止(シンボリックリンクで直結) |

## レポの対応(済み)

- configs.jsonc の `opencode.overrides.plugin` を `plugins` に改め、
  quota と handoff を外した。
- `bin/setup.sh` — OpenCode 本体を v2 インストーラで入れ、プラグインを
  `opencode plugin add` + `update` で入れるようにした。
- `opencode/plugin/goal.js` / `loop.js` を v2 形式に移植。イベントは
  `session.step.ended`(トークン会計とラップ特定)と
  `session.execution.*`(ターン終端)を読む。
- `opencode/command/goal.md` / `loop.md` を削除(プラグインがコマンドを
  登録する)。`bin/opencode-plugin.template` を削除し、
  `make setup-skills` はプラグインをコマンドと同じくシンボリックリンクで
  入れる。v1 時代の shim は実行時に置き換わる。

## 既存チェックアウトの手順

```bash
git pull
opencode plugin remove @slkiser/opencode-quota 2>/dev/null || true
opencode plugin remove opencode-handoff 2>/dev/null || true
make opencode-global    # opencode.json から上の2つが消える
make setup-skills       # goal/loop がシンボリックリンクに入れ替わる
rm -f ~/.config/opencode/command/goal.md ~/.config/opencode/command/loop.md
```

`opencode/command/*.md` を消したので、`~/.config/opencode/command/` に
残るリンクは切れている。`make setup-skills` は切れたリンクを報告するだけで
消さないので、手で消す。

古い `~/.config/opencode/plugin/goal.js` / `loop.js`(v1 shim)は
`make setup-skills` が検出して置き換える。`opencode` の再起動で
プラグインエラーが消える。

## 確認

```bash
opencode plugin list   # oc-tps と dcp だけが載っていること
opencode               # プラグインエラーのダイアログが出ないこと
```

TUI 内では `/plugins` で各プラグインの状態を見られる。quota は v5.0.0 が
出たら `OPENCODE_PLUGINS`(bin/setup.sh)と configs.jsonc の
`opencode.overrides.plugins` に戻せばよい。
